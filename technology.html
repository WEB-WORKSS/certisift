How We Use Amazon Web Services

CertiSift's production platform is designed as a serverless workflow on AWS: certificates go into encrypted storage, Amazon Textract and Amazon Bedrock turn scanned and unfamiliar layouts into structured results, and AWS Lambda checks them against your specification. Today the verification engine runs in the browser in the live demo.

  1. 01

    Data collection

    QA users upload certificates and specifications through an authenticated API.

    Amazon API GatewayAmazon S3
  2. 02

    Secure storage

    Certificates encrypted with customer-managed keys; specifications, suppliers and results stored per tenant.

    Amazon S3AWS KMSAmazon DynamoDB
  3. 03

    Processing

    Orchestrates extract → interpret → match → report, and runs specification matching and anomaly checks.

    AWS Step FunctionsAWS Lambda
  4. 04

    AI intelligence

    Reads scanned and PDF certificates, interprets unfamiliar layouts and explains findings.

    Amazon TextractAmazon Bedrock
  5. 05

    Application experience

    Sign-in with tenant isolation and roles; logs, metrics and alerts behind the web app.

    Amazon CognitoAmazon CloudWatch

These services are proposed, not yet deployed. The live demo runs in your browser on sample data.

  • Amazon Textract: Extract text and tables from scanned and PDF certificates.
  • Amazon Bedrock: Interpret unfamiliar layouts, normalise parameter names, assist anomaly review.
  • AWS Lambda: Run extraction, matching and report generation steps.
  • AWS Step Functions: Orchestrate the upload → extract → interpret → match → report workflow.
  • Amazon S3: Encrypted storage of uploaded certificates and generated reports.
  • Amazon DynamoDB: Supplier records, specifications and verification results.
  • Amazon API Gateway: Secure API for the web app and future integrations.
  • Amazon Cognito: User sign-in and per-customer tenant isolation.
  • AWS KMS: Customer-managed encryption keys for documents and records.
  • Amazon CloudWatch: Logs, metrics and alerting.
Running now

Verification engine

Runs in the browser in the live demo.

  • Header extraction: supplier, product, lot, dates, signatory
  • Result parsing incl. scientific notation, “<10”, decimal commas, “Not detected”
  • Parameter aliases and unit equivalence (ppb ↔ µg/kg, ppm ↔ mg/kg)

  • Outlier, lot-reuse and copied-value detection against supplier history
Proposed architecture

Production platform on AWS

How a certificate becomes a release decision

  1. 1. Upload

    A QA user uploads a certificate through Amazon API Gateway. The file goes to Amazon S3, encrypted with the customer's AWS KMS key.

  2. 2. Extract

    AWS Step Functions starts the workflow. Amazon Textract reads text and tables, including scanned PDFs.

  3. 3. Interpret

    Amazon Bedrock maps unfamiliar layouts and parameter names to the specification. Low-confidence mappings are shown for review.

  4. 4. Check

    AWS Lambda runs specification matching and anomaly checks and stores results in Amazon DynamoDB.

  5. 5. Decide and report

    Reviewers sign in with Amazon Cognito, record release decisions and export reports. Amazon CloudWatch records logs and alerts.

Access and encryption (as designed)

  • Encryption in transit (TLS) and at rest with customer-managed AWS KMS keys
  • Each customer's certificates and records partitioned by tenant
  • Least-privilege IAM roles for every Lambda function
  • API requests authorised with Cognito tokens and checked on the server
  • Bedrock is called only with the customer's own documents; they are not used to train models

Proposed, not yet deployed

Amazon Textract · Amazon Bedrock · AWS Lambda · AWS Step Functions · Amazon S3 · Amazon DynamoDB · Amazon API Gateway · Amazon Cognito · AWS KMS · Amazon CloudWatch
